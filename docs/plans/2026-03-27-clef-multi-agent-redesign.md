# Clef Compose 多 Agent 模式改进设计

> **Status:** 设计阶段 — 核心流程 + 简谱环节已完成

## 核心问题

当前多 Agent 流程是"静默生产模式"——用户给一句描述，系统全自动跑完 8 步输出成品。导致：
1. 信息收集不足，系统靠猜测选配器（方波代替管弦乐）
2. 方向不可控，直到成品出来才发现偏差
3. 试错成本高，30 秒曲子要跑完整个 pipeline 才能听到

## 改进后的完整流程

### MA-Step 0: 交互式需求收集（新增）

根据用户描述，逐步询问缺失的关键信息。每步选项依赖前序回答。

**必要信息（缺一不可）：**

| 顺序 | 信息 | 选项来源 | 说明 |
|------|------|---------|------|
| 1 | 游戏类型/场景 | 根据用户描述动态生成 | 如用户说 JRPG → 战斗/Boss/村庄/主菜单/过场 |
| 2 | 音乐风格 | 根据场景给出合理选项 | 如 JRPG 战斗 → 经典管弦/现代电子/8-bit |
| 3 | 情绪/氛围 | 固定选项 | 激昂/紧张/悲伤/宁静/史诗/暗黑 |
| 4 | 时长 | 固定选项 | 30 秒/1 分钟/2 分钟/自定义 |
| 5 | 乐器组合 | 根据上面所有回答，给出 3-4 个备选方案 | 从 theory.md 配器方案中选择 |
| 6 | 主打乐器 | 根据选定的乐器组合，给出 3-4 个备选 | 从组合中提取旋律乐器选项 |

**可选信息（用户没说就不问）：** 参考曲（--ref 已有）、调性偏好、BPM 范围、是否循环

**输出：** 结构化需求参数 → 进入 MA-Step 1

### MA-Step 1: Producer 规划（现有，微调）

需求参数 → plan.json → 展示给用户确认（调性、BPM、段落结构、配器方案）

### MA-Step 2: 两级打样（新增，核心改进）

#### MA-Step 2a: 方向小样

- **时长：** 8-16 拍（约 5-10 秒），只覆盖 1-2 个段落
- **流程：** Harmonist 简化和弦 → Composer 输出简谱 → 审核简谱 → 简谱转 JSON → 可试听片段
- **用户决策：** 旋律走向、风格感觉、情绪对不对
- **不满意：** Composer 重写简谱 / 回到 MA-Step 1 调 plan

#### MA-Step 2b: 完整初版

- **时长：** 完整长度（如 72 拍 / 30 秒）
- **复用：** 2a 确定的旋律方向和和弦风格
- **流程：** Harmonist 完整和弦结构 → Composer 扩展简谱 → 审核简谱 → 转换 JSON → 可试听完整 MIDI（旋律+和弦）
- **用户决策：** 段落过渡、高潮位置、循环衔接
- **不满意：** 局部修改 / 回到 2a

### MA-Step 3: 完整生产（整合原 MA-Step 2-6）

```
并行生成：Harmonist 完整版 chords + Rhythmist bass + drums
  ↓
Composer 精修 melody（复用 2b 的简谱产物，转为 JSON）
  ↓
Orchestrator 生成表现力层
  ↓
整合 + validate_clef.py + 输出
```

审查机制变化：
- ~~原 MA-Step 3/5 人工审查~~ → 简谱审核 Agent（在打样环节已覆盖）
- validate_clef.py 在最终整合时覆盖格式合规

### MA-Step 4: 输出（现有 MA-Step 8）

## 用户确认点（4 个）

| 确认点 | 看到什么 | 决策 |
|--------|---------|------|
| MA-Step 0 | 结构化需求参数 | 确认/修改 |
| MA-Step 1 | plan.json（调性、BPM、结构、配器） | 确认/修改 |
| MA-Step 2a | 短样简谱 + 审核报告 + 5-10 秒试听 | 方向对不对 |
| MA-Step 2b | 完整简谱 + 审核报告 + 30 秒试听 | 结构好不好 |

## 流程对比

| | 旧流程 | 新流程 |
|--|--------|--------|
| 步骤数 | 8 步 | 5 步 |
| 用户确认点 | 0 个 | 4 个 |
| 旋律质量保障 | 依赖 Composer 自觉 + 事后审查 | 打样 + 简谱审核 + 自动合规 |
| 配器准确性 | 系统猜测 | 用户在 Step 0 直接选择 |
| Agent 调用 | 6 次（含 2 次审查） | 4-6 次（取决于打样迭代） |
| 旋律产出方式 | Composer 直接输出 JSON | Composer 输出简谱 → 审核 → 转换 JSON |

## 简谱环节设计

### 核心决策：简谱先于 JSON

**旧方式：** Composer → melody.json (MIDI) → 转简谱 → 审核
**新方式：** Composer → 简谱文本 → 审核简谱 → 转换为 melody.json

**理由：**
1. Composer 的思维语言是音乐（1-2-3-4-5-6-7），不是 MIDI 编号
2. 简谱上审核更直观 — 大跳 `1→5` 一眼可见，不需要算半音差
3. 创作和编码解耦 — 简谱→JSON 是确定性转换，零创意损失
4. 简谱对用户和修改 Agent 都可读

**适用范围：** 仅旋律轨道。和弦和鼓组仍使用 JSON 格式。

### 简谱文本格式规范

**排版目标：** 同时满足人类可读性和机器可解析性，输出格式应与真实简谱一致。

**头部：**
```
1=D  4/4  BPM=140
```

**音符元素：**

| 元素 | 写法 | 含义 |
|------|------|------|
| 基本音 | `1` `2` `3` `4` `5` `6` `7` | 音阶度数 |
| 升号 | `#4` `#5` | 升半音 |
| 降号 | `b3` `b7` | 降半音 |
| 高八度 | `1̇`（上方点） | 高一个八度 |
| 低八度 | `1̣`（下方点） | 低一个八度 |
| 四分音符 | `1` | 1 拍（无标记） |
| 八分音符 | `1\u0332`（下划线） | 0.5 拍 |
| 十六分音符 | `1\u0332\u0332`（双下划线） | 0.25 拍 |
| 附点 | `1.` | 时值 ×1.5 |
| 延音 | `1 -`（横杠） | 持续到下一拍位 |
| 休止 | `0` | 静默 |
| 力度 | `(f)` `(mf)` `(mp)` `(p)` | velocity 范围 |
| 小节线 | `\|` | 拍号对应的位置 |
| 双小节线 | `\|\|` | 段落边界 |
| 段落标记 | `[A]` `[B]` | 段落 ID |

**排版规则：**
- 力度标记单独一行，对齐到变化位置上方
- 段落标题单独一行，力度在标题下方
- 音符按拍位等宽对齐（每拍占固定宽度）
- 小节线 `|` 分隔，段落边界用 `||`

**完整示例：**
```
1=D  4/4  BPM=140

[A] 引入
        (mp)
| 2   4   3 -  | 4   3   2 -  |
| 2   4   3   5 | 6   5   3 -  |

[B] 发展
        (f)
|| 5   6   7 -  | 1̇   7   5 -  |
| 5   6   7   1̇ | 2̇   1̇   6 -  |
```

### 简谱审核规则（5 维度 10 项检查）

审核 Agent 读取简谱文本 + chords.json，输出结构化报告。

#### 维度 1：音高合理性

| 检查项 | 检测方式 | 等级 |
|--------|---------|------|
| 大跳检测 | 度数跳变 >5 (WARN) / >7 (FAIL) | FAIL/WARN |
| 音域检测 | 高低八度标记跨度 >2 (WARN) | WARN |
| 增减音程 | `#1→b3` 等非常规进行未合理解决 (WARN) | WARN |

#### 维度 2：调式内聚性

| 检查项 | 检测方式 | 等级 |
|--------|---------|------|
| 非调内音解决 | 变音后 1 拍内回到调内音 (WARN) | WARN |
| 骨干音频率 | `1` 和 `5` 出现占比 >25% (PASS) / <15% (FAIL) | FAIL/PASS |

#### 维度 3：节奏规范性

| 检查项 | 检测方式 | 等级 |
|--------|---------|------|
| 小节时值 | 每小节总拍数正确 (FAIL) | FAIL |
| 节奏多样性 | 至少 3 种不同的节奏型 (WARN) | WARN |

#### 维度 4：乐句结构

| 检查项 | 检测方式 | 等级 |
|--------|---------|------|
| 乐句长度 | 2/4/8 小节为正常，异常长度 (WARN) | WARN |
| 动机重复 | 首尾乐句共享动机素材 (INFO) | INFO |
| 高潮位置 | 最高音出现在乐曲 60-80% 位置 (WARN) | WARN |

#### 维度 5：和声隐含（需要 chords.json）

| 检查项 | 检测方式 | 等级 |
|--------|---------|------|
| 强拍和弦对齐 | 每小节第 1 拍的音落在当前和弦构成音上 (WARN) | WARN |

### 审核报告格式

报告同时满足人类可读和修改 Agent 可消费两种需求。

**示例输出：**
```
【审核报告】
总体评价：B-（基本规范，但存在3处明显不自然）

[FAIL] 音高合理性
  - 第5小节: 连续减五度跳进 4→b7→3，建议改为纯五度 4→1或分解进行 4→5→7
  - 第13小节: 八度大跳 3→3̇ 未级进收回

[WARN] 节奏规范性
  - 第9-12小节: 节奏型 × 4 重复，建议第11小节加入附点

[INFO] 乐句结构
  - 第17小节: 高潮音 2̇ 仅持续 1 拍，建议延长至 2 拍

[PASS] 调式内聚性 — 骨干音 1(18%) 5(14%) 分布合理
[PASS] 和声隐含 — 强拍音与和弦对齐率 92%
```

**等级定义：**

| 等级 | 含义 | 标准 |
|------|------|------|
| A | 优秀 | 0 FAIL, ≤1 WARN |
| B+ | 良好 | 0 FAIL, 2-3 WARN |
| B | 合格 | 0 FAIL, 4-5 WARN |
| B- | 基本合格 | 1-2 FAIL |
| C | 需要修改 | 3+ FAIL |

### 简谱转 JSON 转换规则

确定性转换，不需要 LLM 参与。给定 plan.json 的 root_pitch 和 scale_intervals。

**音高转换：**
- 度数 `n` → MIDI pitch = root_pitch + scale_intervals[n-1] + octave_offset × 12
- `#n` → 在 scale interval 基础上 +1 半音
- `bn` → 在 scale interval 基础上 -1 半音
- `ṅ` → +12, `ṇ` → -12

**时值转换：**
- 无标记 → 1.0 拍
- `\u0332`（下划线）→ 0.5 拍
- `\u0332\u0332`（双下划线）→ 0.25 拍
- `.`（附点）→ 前值 × 1.5
- `-`（延音）→ 持续到下一拍位
- `0`（休止）→ 增加 start 偏移

**Velocity 转换（范围 + 线性分配）：**

| 力度标记 | velocity 范围 | 分配方式 |
|---------|-------------|---------|
| `(f)` | 100-110 | 段内线性递增 |
| `(mf)` | 85-95 | 段内线性递增 |
| `(mp)` | 70-80 | 段内线性递增 |
| `(p)` | 55-65 | 段内线性递增 |
| 未标记 | 继承前值，默认 80 | — |

线性分配含义：段内第一个音符取范围下限，最后一个取上限，中间线性插值。即使简谱只标记了粗略力度，输出 MIDI 也有自然力度渐变。

**拍位计算：**
- 从左到右逐字符解析，累加时值得到 start
- 小节线 `|` 重置拍位计数器

## theory.md 扩充计划

### 现状

theory.md 当前 440 行，和声内容丰富但旋律内容薄弱。新流程以旋律为核心（简谱先于 JSON），旋律知识是 Composer 和审核 Agent 的基础。

### 需要新增的章节（5 个）

#### 1. 简谱记谱法（新增章节）

给 Composer 和审核 Agent 提供统一的简谱格式参考：
- 简谱基本符号（度数、升降号、八度点、休止符）
- 时值标记（四分/八分/十六分/附点/延音线）
- 力度标记（f/mf/mp/p/pp）及其 velocity 对应范围
- 小节线和段落标记
- 排版规范（拍位对齐、力度行位置、段落标题格式）
- 完整示例（至少 2 个：简单旋律 + 复杂旋律含变音和八度变化）

#### 2. 旋律写作技法（新增章节）

从 Composer agent prompt 中提取并扩展，作为理论参考：
- **动机定义与类型**：短动机（2-3 音）、长动机（4+ 音）、节奏动机、音高动机
- **动机发展 6 法**：重复、变奏（节奏/音高/力度）、模进、倒影、扩展、截断
- **变奏技巧细化**：装饰音变奏、节奏拉伸/压缩、音区移位、调式交替
- **乐句构建**：乐句长度（2/4/8 小节常见）、前句/后句关系（问答式、平行式）、弱起技巧
- **旋律建筑**：音域布局（低→高→低、阶梯式上升）、高潮位置（60-80% 黄金分割点）、段落对比（音区/密度/节奏）
- **旋律与和弦配合**：强拍和弦音、弱拍和弦外音、经过音/邻音/倚音的使用时机

#### 3. 旋律音程指南（新增章节）

系统性的音程使用规则：
- **自然音程分类**：
  - 极常用（级进）：大二度、小二度、小三度、大三度
  - 常用（小跳）：纯四度、纯五度
  - 需谨慎（大跳）：大六度、小七度、大七度
  - 需特殊处理：增四度/减五度（三全音）
- **大跳处理规则**：大跳后反向级进收回、不超过连续 2 次同向大跳、大跳必须落在和弦音上
- **增减音程**：增二度回避规则（已有，从现有内容迁移）、增四度的解决方式
- **音域约束**：1.5 个八度（18 半音）为推荐上限、高潮段可扩展到 2 个八度

#### 4. 乐句结构（扩展现有内容）

现有的 2 行"乐句长度建议"扩展为完整章节：
- **常见乐句长度**：2 小节（短句）、4 小节（标准句）、8 小节（长句）
- **乐句关系类型**：平行（相同动机不同结尾）、对比（新材料）、问答式（前句不稳定→后句解决）
- **乐句连接技巧**：抢先进入、弱起、经过音连接、休止符呼吸（详细展开现有 2 行）
- **终止式类型**：正格终止、变格终止、半终止、阻碍终止（现有内容迁移并扩展）
- **段落结构**：二段式（AB）、三段式（ABA）、通谱体、回旋曲式

#### 5. 风格旋律特征（新增章节）

与 theory.md 现有配器方案表对齐，为每种风格添加旋律特征描述：
- **经典 JRPG 战斗**：级进为主、四度跳进多、上行模进发展、高音区铜管式旋律
- **现代 JRPG 战斗**：大跳+切分、电吉他式推弦、快速音阶跑动
- **RPG Boss**：全音域覆盖、铜管式号角动机、模进递进、高潮持续长音
- **8-bit/Chiptune**：音域窄（1 个八度内）、跳跃式旋律、重复性高
- **史诗管弦**：长线条旋律、渐强式乐句、弦乐式连奏、休止符制造呼吸
- **暗黑/恐怖**：小音域低区、减音程/增音程、不规则的短动机重复
- **悲伤/抒情**：级进为主、下行旋律多、装饰音（颤音/波音）、慢速长音
- **村庄/探索**：五声音阶倾向、简单动机、重复+微变、休止多
- **主菜单**：宽广旋律、大跳点缀、长音+短音交替

每个风格条目包含：音域范围、常用音程、节奏特征、动机特征、代表性旋律模式示例
