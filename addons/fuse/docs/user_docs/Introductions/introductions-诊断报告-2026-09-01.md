## 二、定位断层：全系列与新工具定位的两条腿

新定位（README 口径）：**「从 AI 原型到工程代码的非破坏性桥梁」**，三段人群：不写代码的创作者 / AI 辅助开发者 / 工程团队。

15 篇全覆盖了「手搭」这条腿，但 grep 全系列：**`AI 生成` / `preset` / `handoff` / `交接` 零命中**。两条腿缺了一条：

### 2.1 01-总览篇：定位段重写（门面，优先级最高）

- 现开头「让策划和美术也能搭逻辑」只覆盖人群①，且是旧单一定位
- 建议开头改为桥梁叙事：原型侧（AI 生成 preset JSON / Inspector 调参）+ 出口侧（交接工件给 AI agent 写脱离 Fuse 的代码）+ 非破坏性
- 「三句话理解核心模型」结构很好，保留；加第四句：**「怎么交给 AI / 怎么毕业」——preset schema 让 AI 直接生成合规 JSON，交接工件让工程代码无缝毕业**

### 2.2 新增第 16 篇：《AI 协作与毕业交接》（最大空白，最强卖点）

建议大纲：
1. **Preset AI 生成闭环**——schema 化组件清单（310 组件+条件参数门控）、离线校验器（四层规则/退出码门禁）、eval 回归基线；附实操案例「让 AI 生成一份冷却触发逻辑 preset」
2. **场景拓扑导出**——export_topology CLI、产物名=场景文件茎、溯源字段
3. **System 工件**——derive_systems 推导、人工确认、validate_system 校验（含 topology_digest 漂移检测）
4. **handoff-packer 一键打包**——自包含交接包结构（系统划分/拓扑/preset/语义契约/验收清单/组件 schema/基建模板），金样例 `fuse_generated/handoff/game_flow/` 走查
5. **出口方向说明**——derive/validate 是主线；`export_system` GDScript 生成是实验特性（引用 57-graduation-exporter-guide）
6. **非破坏性承诺**——源 Trigger 不动、随时回滚、不写代码的用户留在运行时

### 2.3 14-Topology 篇：补「新角色」一节

现内容（面板+静态分析）仍有效，补一节「**作为交接工件的源头**」：export_topology CLI 用法、JSON 如何流向 derive_systems → handoff 包。约 20-30 行。
