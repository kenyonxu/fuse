# 变量绑定使用指南

> **目标**: 讲清 Fuse 指令参数的"双轨"能力——同一个参数既能填固定值，也能改成运行时从变量读取。这是把静态配置变成动态逻辑的关键一步。
>
> **适用对象**: Fuse 插件使用者

---

## 这是什么？

大多数指令的参数有两种填法：**直接值**（DIRECT，Inspector 里写死一个数/字符串/节点）或**变量**（VARIABLE，运行时从三层变量系统读取）。同一条指令因此能同时服务两种场景——策划要固定效果时填直接值，逻辑需要动态计算时绑变量，一条指令顶两条用。

在 Inspector 里认这个特征：参数组里出现 `use_variable_for_xxx` 勾选框的指令就是支持双轨的。它遍布变换、动画、UI、音频、相机等大多数指令域，也覆盖相当一部分条件组件。

## Inspector 里的实际形态

以 `SetScale`（设置缩放）为例：

```
☑ use_variable_for_target     ← 不勾：target 直接选节点
                                 勾选：出现 target_variable（变量名）+ target_scope（作用域）
offset: (1.0, 1.0)            ← offset 参数本身也可以有独立的 use_variable_for_offset 轨道
```

再如 `SetUIText`（设置 UI 文本）：文本内容可以从变量读——血量数字、倒计时、玩家名，凡是会变的东西都该走变量轨，而不是每次写值再触发一次指令。

要点有三个：

1. **每个参数独立开关**：`use_variable_for_target` 和 `use_variable_for_offset` 互不影响，可以只把"位置"绑变量、"偏移"留固定值。
2. **勾选后参数区切换形态**：直接值输入框消失，换成变量名 + 作用域下拉；取消勾选即回到直接值，原值不丢。
3. **变量名在编辑期不校验存在性**：变量是运行时解析的，写错名字不会在 Inspector 报错，但执行时读不到值——配合变量监视器排查（见文末常见问题）。

## 作用域怎么选

绑变量时必须选一个作用域，规则与[变量系统指南](01-variable-system-guide.md)一致：

| 作用域 | 什么时候用 |
|--------|-----------|
| LOCAL | 默认。本次指令序列内 `SetVariable` 存的中间值，序列结束即失效 |
| GLOBAL | 跨场景共享的状态：血量、金币、进度等持久数据 |
| SCOPE | 场景子树内共享：同一容器下的多个 Trigger 读写同一份，子树销毁自动清理 |

一个实用判断：**谁写谁读**。写入方和读取方在同一条逻辑线里 → LOCAL；写入方在别的场景/系统 → GLOBAL；写入方在同个子树的其他 Trigger → SCOPE。

## 与表达式系统的分工

[表达式系统](05-expression-guide.md)（`MathExpression` / `StringExpression` / `ExpressionCondition`）和变量绑定解决的是两类"动态"：

- **变量绑定 = 引用**：参数的值**来自**某个已存在的变量，不加工。
- **表达式 = 计算**：参数的值需要**算出来**（多变量运算、格式化、条件求值），算完可存回变量再被绑定引用。

典型组合是三级流水：表达式算出结果 → `SetVariable` 存入 → 下游指令把参数绑到这个变量。需要即时计算的就直接用表达式的输出，不必绕道变量。

## 与指令生成器的关系

[指令生成器](06-instruction-generator-guide.md)为你的自定义节点方法生成指令时，可以勾选"使用变量"生成**变量绑定版**——生成出的指令同样带 `use_variable_for_xxx` 轨道，与内置指令的双轨行为一致。内置与生成、直接值与变量，四象限在这个体系里是同构的。

## 常见问题

### 绑定了变量但读不到值？

九成是作用域选错：变量在 GLOBAL，绑定时选了 LOCAL。先用[变量监视器](56-variable-watcher-guide.md)（编辑器底部 Dock，按作用域分标签页）确认变量实际存在哪一层，再回来对齐作用域下拉。

### 运行时报"变量不存在"但监视器里看得到？

检查拼写与作用域是否完全一致；若变量是执行中才创建的，确认绑定指令的执行时机晚于 `CreateVariable` / `SetVariable`。

### 直接值和变量来回切换，逻辑哪个生效？

以勾选框当前状态为准：勾选 = 运行时读变量（直接值被忽略）；未勾选 = 用直接值。两套配置各自保留，切换无破坏。
