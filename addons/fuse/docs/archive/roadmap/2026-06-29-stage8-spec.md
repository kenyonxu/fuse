## 2. 子任务 8a — NodePath 重映射

### 2.1 现状

[FusePresetDeserializer.deserialize(preset, mapping)](../../editor/serialization/fuse_preset_deserializer.gd#L18) 已有 `mapping` 参数 + `_apply_nodepath_mapping_node()` 方法。L2/L3/L4 导入时调 `_apply_nodepath_mapping_node(node, mapping)`。

**但调用方不提供 mapping**（mapping 为空 {}）= NodePath 不重映射 = 预设应用到新场景时 NodePath 断裂。

### 2.2 需求

导入预设时：
1. **检测** 预设内所有 NodePath 引用（相对原始 Trigger 节点的路径，如 `..` / `../Player`）
2. **自动匹配** 目标场景中同名节点（模糊匹配 → 生成 mapping 建议）
3. **UI 确认** 导入对话框显示映射表（旧路径 → 新路径），用户确认/修改
4. **应用** mapping 传给 deserializer，重映射 NodePath

### 2.3 设计

#### 自动匹配策略

```
预设 NodePath ".."（父节点）
  → 目标场景：导入位置（目标 Trigger 节点）的父节点
  → mapping[".."] = NodePath(目标 Trigger 的父路径)

预设 NodePath "../Player"（兄弟节点）
  → 目标场景：目标 Trigger 的父节点下的同名子节点 "Player"
  → mapping["../Player"] = NodePath(...)

预设 NodePath "PlayerShip"（子节点）
  → 目标场景：目标 Trigger 下的同名子节点
  → mapping["PlayerShip"] = NodePath(...)
```

**匹配优先级：**
1. 精确路径结构匹配（相对路径层级 + 节点名）
2. 全局节点名匹配（场景中唯一名）
3. 无匹配 → 标红，用户手动选

#### 导入 UI 扩展

[PresetImportDialog](../../editor/serialization/) 扩展（或新建 NodePathMappingDialog）：

```
┌─ NodePath 重映射 ─────────────────────┐
│  旧路径（预设）  →  新路径（当前场景）   │
│  ..              →  [GameScene]  ✓     │
│  ../Player       →  [GameScene/Player] ✓│
│  EnemySpawner    →  ⚠ 未找到 [手动选▼] │
│                                        │
│  [自动匹配]  [全部应用]  [取消]        │
└────────────────────────────────────────┘
```

- 绿色 ✓ = 自动匹配成功
- 黄色 ⚠ = 无匹配，OptionButton 下拉手动选场景节点
- 用户确认后，mapping 传给 deserializer

### 2.4 约束

- **L1（纯 ActionRunner）不涉及 NodePath 重映射**（指令数组直接复制，无节点上下文）。L2/L3/L4 才有。
- NodePath 引用来源：InstructionAnalyzer._extract_nodepaths（Stage 6.5 反射 + 命名启发式提取的 `*_node`/`*_node_path` 属性）。
- mapping 格式：`{old_nodepath_str: NodePath(new_path)}`（字符串 key → NodePath value，兼容现有 `_apply_nodepath_mapping_node`）。

### 2.5 不做

- ❌ 复杂模糊匹配（正则/编辑距离）—— V1 用精确名 + 层级匹配
- ❌ 自动学习用户选择（ML/历史）—— V1 纯手动确认
- ❌ 批量导入多预设的统一映射

## 3. 子任务 8b — 逻辑流 GraphEdit

### 3.1 现状

[FuseTopology](../../editor/topology/fuse_topology.gd) 用 Tree（平铺列表）渲染 Trigger + 嵌套指令。Stage 5 交付。

[gdscript-ast-flow GDSVirtualGraphEdit](E:/GitHub/gdscript-ast-flow/addons/gdscript_ast/editor/graphs/gds_virtual_graph_edit.gd) 提供 `set_graph(nodes: Dictionary, p_edges: Array)` —— 零耦合通用图渲染（虚拟化 + 布局 + 连线）。

### 3.2 需求

Topology 升级：选中 Trigger → 右侧详情从 RichTextLabel 文字 → **GraphEdit 节点-连线图**（可视化指令链 + if/else 分支）。

### 3.3 设计

#### FuseGraphBuilder（新建，~150 行）

将 InstructionAnalyzer.analyze_trigger 的 report 转为 `{nodes, edges}`：

```
Trigger (root node)
  ├── Event (节点)
  ├── Instruction A (节点)
  ├── If/Then (节点)
  │   ├── condition: true branch
  │   │   ├── Instruction B
  │   │   └── Instruction C
  │   └── condition: false branch
  │       └── Instruction D
  └── Instruction E

nodes = {
  "trigger": {title: "Trigger", type: "trigger", ...},
  "event": {title: "OnInputKey", type: "event", ...},
  "inst_a": {title: "SetVariable", type: "instruction", ...},
  "if_1": {title: "If: health > 0", type: "branch", ...},
  "inst_b": {title: "MoveNode", type: "instruction", ...},
  ...
}

edges = [
  {from: "trigger", to: "event", label: ""},
  {from: "trigger", to: "inst_a", label: ""},
  {from: "trigger", to: "if_1", label: ""},
  {from: "if_1", to: "inst_b", label: "true"},
  {from: "if_1", to: "inst_d", label: "false"},
  ...
}
```

#### 节点类型 + 颜色

| 类型 | 颜色 | 内容 |
|---|---|---|
| Trigger | 蓝 | Trigger 名 + Event 名 |
| Instruction | 绿 | 指令显示名 + 关键参数 |
| Branch (if/else) | 橙 | 条件表达式 |
| 变量引用 | 虚线边 | （可选）变量名标注 |

#### 集成方式

FuseTopology 右侧详情区（`_detail: RichTextLabel`）替换/并列 GraphEdit：
- **选中 Trigger** → 右侧显示 GraphEdit（指令链图）
- **未选中** → 空 / 提示
- Tree（左侧）保留（导航 + 全场景概览）
- 可切换 GraphEdit / RichTextLabel（Tab 或 Toggle）

### 3.4 复用 gdscript-ast-flow

- **GDSVirtualGraphEdit** → 拷贝到 `addons/fuse/editor/topology/`（或 third_party/），与 gdscript_ast 本地副本共用
- **GDSGraphNode** → 复用（节点渲染）
- **GDSGraphLayout** → 复用（自动布局）
- **不可复用**：`GDSCallGraphView` 等 builder 层（强耦合 AnalysisResult）—— 自写 FuseGraphBuilder

> gdscript_ast 已在本地（.gitignore），GDSVirtualGraphEdit 可直接 preload。

### 3.5 不做

- ❌ 节点拖拽/编辑（只读可视化）
- ❌ 多 Trigger 同时显示（单个 Trigger 的指令链）
- ❌ 实时更新（选中 Trigger 刷新即可）

## 5. 风险

| 风险 | 缓解 |
|---|---|
| NodePath 自动匹配覆盖率（场景结构差异大） | V1 精确名 + 层级；无匹配手动选；不强制自动 |
| GraphEdit 性能（大 Trigger 50+ 指令） | GDSVirtualGraphEdit 有虚拟化（MAX_NODES=500） |
| GDSVirtualGraphEdit 拷贝 vs preload gdscript_ast | gdscript_ast 本地已 .gitignore，可直接 preload（不拷贝） |
| 导入 UI 复杂度（NodePath 映射表交互） | 基于现有 PresetImportDialog 扩展，不新建对话框 |

## 6. 验收标准

### 8a NodePath 重映射
1. 导入 L2/L3/L4 预设到**不同场景** → NodePath 映射对话框出现
2. 自动匹配同名节点 → 绿色 ✓
3. 无匹配节点 → 手动选 → 应用
4. 导入后 NodePath 正确指向目标场景节点
5. L1 预设导入不受影响（无 NodePath 重映射）

### 8b GraphEdit
1. Topology 选中 Trigger → 右侧显示指令链 GraphEdit 图
2. if/else 分支可见（true/false 连线 + 标签）
3. 节点显示指令名 + 类型颜色（Trigger 蓝 / Instruction 绿 / Branch 橙）
4. 回归：Tree 左侧导航不受影响
