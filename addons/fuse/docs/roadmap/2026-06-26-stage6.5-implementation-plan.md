## 2. 任务 6.5a — BaseInstruction 自描述接口契约

### 2.1 三个静态虚方法

在 [base_instruction.gd](../../core/base/base_instruction.gd) 的 `_get_instruction_metadata()`（:309）附近，新增三个静态方法。**沿用现有 `_get_instruction_metadata` 模式**（静态方法 + 子类覆写 + 默认实现）。

```gdscript
# ============================================================
# 组件自描述（供 InstructionAnalyzer 静态分析使用）
# 由 codegen 脚本自动生成，请勿手动编辑。
# 详见 docs/roadmap/2026-06-26-stage6.5-implementation-plan.md
# ============================================================

## 返回该指令读写的变量引用。
## 返回: Array[Dictionary]，每项：
##   {
##     "prop": String,          # 变量名属性（如 "target_variable"）
##     "scope_prop": String,    # 配对的作用域属性（如 "target_variable_scope"），可为空 ""
##     "mode": String,          # "read" / "write" / "read_write"
##     "condition_prop": String # 仅当该变量访问受开关控制时的属性名（如 "set_with_another_variable"），可为空 ""
##   }
static func _get_variable_accesses() -> Array:
	return []

## 返回该指令引用的场景节点属性名（仅补充类型非 NodePath 的，如用 String 存的 *_node）。
## 类型为 NodePath 的属性由反射自动覆盖，无需在此声明。
## 返回: Array[String]
static func _get_nodepath_props() -> Array:
	return []

## 返回该指令涉及的自定义信号信息。
## 返回: Dictionary
##   {
##     "declared": Array[String],  # 指令声明/代表的信号名（如 EmitSignal 的 signal_name）
##     "emitted": Array[String]    # 指令执行时 emit 的信号名
##   }
static func _get_signal_info() -> Dictionary:
	return {"declared": [], "emitted": []}
```

### 2.2 设计要点

- **静态方法**（非实例）：分析时组件可能未实例化，必须可从 `script._get_xxx()` 直接调用，与 `_get_instruction_metadata()` 一致。
- **默认空实现**：未 codegen 的组件返回空，InstructionAnalyzer 静默跳过，不破坏现有行为。
- **为什么 `nodepath_props` 只补非类型化的**：[instruction_analyzer.gd:112](../../editor/analysis/instruction_analyzer.gd#L112) 已用 `prop.type == TYPE_NODE_PATH` 反射覆盖类型化 NodePath。codegen 只补漏网（属性名是 `*_node`/`*_node_path` 但类型是 String 的）。
- **`mode` 字段 V1 用命名启发式**（见 3.4），精确版作 6.5b 可选增强。

### 2.3 验收

- BaseInstruction 编译无错
- 默认实现返回值符合契约（空 Array / 空 Dictionary）
- 任一现有组件（如 SetIntVariable）手动覆写一个方法，`script._get_variable_accesses()` 能正确调用返回

### 3.3 核心分析算法（伪代码）

```gdscript
for file_path in scan_fuse_instruction_dirs():
    source = FileAccess.open(file_path).get_as_text()
    ast = GDScriptParser.new().parse(GDScriptTokenizer.new().tokenize(source))
    if parser.error != "": continue  # 跳过解析失败，记录日志

    class_name = ast.class_name
    var accesses := []
    var nodepath_props := []
    var signal_info := {"declared": [], "emitted": []}

    # (1) 变量属性提取
    var export_props := _collect_export_vars(ast)  # [{name, type}]
    for prop in export_props:
        if not prop.name.ends_with("_variable"): continue
        if prop.type != TYPE_STRING: continue       # 变量名属性是 String
        var scope_prop := _find_scope_pair(prop.name, export_props)  # target_variable → target_variable_scope
        var mode := _infer_mode(prop.name)          # 见 3.4
        var condition := _infer_condition(prop.name, source)  # 见 3.5
        accesses.append({"prop": prop.name, "scope_prop": scope_prop, "mode": mode, "condition_prop": condition})

    # (2) NodePath 属性补充（仅非类型化）
    for prop in export_props:
        if prop.type == TYPE_NODE_PATH: continue    # 类型化已反射覆盖
        if prop.name.ends_with("_node") or prop.name.ends_with("_node_path"):
            nodepath_props.append(prop.name)

    # (3) 信号提取（基础版）
    signal_info.emitted = _find_emit_calls(ast)     # emit_signal("x") / sig.emit()

    # (4) 写回标记块
    _write_self_describe_block(file_path, source, class_name, accesses, nodepath_props, signal_info)
```

### 3.4 `mode` 推断规则（V1 命名启发式）

| 属性名前缀 | mode | 依据 |
|---|---|---|
| `target_*` | `"write"` | 目标变量，指令写入它（如 SetVariable） |
| `from_*` | `"read"` | 来源变量，指令读取它（如 SetWithAnotherVariable） |
| 其他 | `"read_write"` | 保守标记，待人工/精确版判定 |

**决策（2026-06-26）：V1 采用命名启发式。** `execute()` 方法体扫描（匹配 `context.set_variable(<prop>, ...)` → write、`context.get_variable(<prop>)` → read）列为**后续增强**，若 V1 启发式覆盖率 < 90% 再启动。

### 3.5 `condition_prop` 推断

某些变量访问受开关控制。例如 [set_int_variable.gd:73](../../instructions/variables/set_int_variable.gd#L73) 的 `set_with_another_variable: bool`——为 true 时才读 `from_variable`。

**决策（2026-06-26）：codegen 尝试推断 `set_with_*` 开关，不保守留空。** 推断规则：
- 扫描组件 bool 型 @export 属性，匹配 `set_with_*` / `use_*` / `enable_*` 模式
- 若开关属性语义匹配某 `from_*` / read 变量（如 `set_with_another_variable` ↔ `from_variable`），填入该变量访问的 `condition_prop`
- 匹配用命名启发式（后缀或语义前缀对齐）；无法匹配时留空 `""`
- **人工校验环节重点复核此项**（最易误判）

### 3.6 输出格式（标记块）

在每个组件文件的 `_get_instruction_metadata()` 静态方法**之后**，插入标记块：

```gdscript
# === BEGIN FUSE SELF-DESCRIBE（codegen 生成，请勿手动编辑）===
static func _get_variable_accesses() -> Array:
	return [
		{"prop": "target_variable", "scope_prop": "target_variable_scope", "mode": "write", "condition_prop": ""},
		{"prop": "from_variable", "scope_prop": "from_variable_scope", "mode": "read", "condition_prop": "set_with_another_variable"}
	]

static func _get_nodepath_props() -> Array:
	return []

static func _get_signal_info() -> Dictionary:
	return {"declared": [], "emitted": []}
# === END FUSE SELF-DESCRIBE ===
```

### 3.7 幂等性

- 用 `# === BEGIN FUSE SELF-DESCRIBE ===` / `# === END FUSE SELF-DESCRIBE ===` 标记包裹
- 重跑时：正则定位标记块，整体替换其内容；标记块外的代码**绝对不动**
- 无标记块的文件：在 `_get_instruction_metadata()` 返回后插入
- 无 `_get_instruction_metadata()` 的文件：记录到跳过日志（这类组件极少）

- codegen 跑完，183 个指令组件中含变量/节点引用的都生成标记块
- 跑两次，第二次 git diff 为空（幂等）

### 4.2 `_extract_variables` 改造骨架

```gdscript
static func _extract_variables(inst, report: Dictionary) -> void:
	var script = inst.get_script()
	if script == null or not script.has_method("_get_variable_accesses"):
		return  # 旧组件无自描述，静默跳过
	var accesses: Array = script._get_variable_accesses()
	for access in accesses:
		var name: String = inst.get(access.get("prop", ""))
		if name.is_empty():
			continue
		var scope_prop: String = access.get("scope_prop", "")
		var scope: int = inst.get(scope_prop) if scope_prop != "" and scope_prop in inst else 0
		var entry := {"name": name, "mode": access.get("mode", "read_write")}
		# 按 scope 分桶（0=LOCAL, 1=SCOPE, 2=GLOBAL），沿用现有 report.variables 结构
		_append_variable_by_scope(report.variables, scope, entry)
```

### 4.3 `_extract_nodepaths` 三重来源 union

```gdscript
static func _extract_nodepaths(inst, report: Dictionary) -> void:
	var found: Array[String] = []
	# 来源 1：组件自描述（codegen 生成，覆盖 String 型 *_node）
	var script = inst.get_script()
	if script and script.has_method("_get_nodepath_props"):
		for prop_name in script._get_nodepath_props():
			_collect_nodepath(inst, prop_name, found, report, false)  # false=非类型化，直接读
	# 来源 2：TYPE_NODE_PATH 反射（覆盖类型化 NodePath）
	for prop in inst.get_property_list():
		if prop.get("type", 0) == TYPE_NODE_PATH:
			_collect_nodepath(inst, prop.name, found, report, true)
	# 来源 3：硬编码 _NODE_PATH_PATTERNS 兜底（未自描述的旧组件）
	for prop_name in _NODE_PATH_PATTERNS:
		_collect_nodepath(inst, prop_name, found, report, false)
```

### 4.4 降级策略

- 组件无 `_get_variable_accesses` 方法（script.has_method 为 false）→ 变量提取返回空（该组件视为无变量引用）。**不再回退到旧 `variable_name` 硬编码**（它本来就失效）。
- 组件无 `_get_nodepath_props` → NodePath 提取仍有 TYPE_NODE_PATH 反射 + 硬编码兜底，覆盖度不降。

## 6. 风险与回滚

| 风险 | 应对 |
|---|---|
| codegen 误判 mode（target/from 之外） | V1 标 read_write 保守值；人工抽查覆盖率，<90% 启动 execute() 扫描增强 |
| codegen 破坏组件文件 | 标记块严格隔离 + 幂等设计；执行前 git 可一键回滚 |
| 183 组件量大，codegen 耗时 | 一次性运行；后续仅新组件跑增量（或 pre-commit 钩子） |
| 组件已有同名静态方法冲突 | 标记块 BEGIN 前检查，冲突则跳过并记日志 |
| BaseInstruction 加方法影响 183 组件 | 静态方法 + 默认实现，子类无需改动即可编译 |

**回滚方案**：任一阶段失败，标记块和 InstructionAnalyzer 改动都是独立 commit，可单独 revert。BaseInstruction 的虚方法是无副作用新增，保留不影响。

## 9. 执行更新（2026-06-27）：方案转向 B（反射 + 命名启发式）

执行中发现原方案 Y（codegen @export AST 扫描）的**核心假设不成立**：

| 发现 | 数据 |
|---|---|
| `_get_property_list` 动态属性组件 | **165/174 (95%)** |
| 纯 `@export var` 组件 | ~7 (4%) |
| codegen @export AST 路径覆盖率 | 最多 26% |

set_int_variable（@export var）是少数派。codegen 的 AST 扫描对 95% 动态属性组件无效（提取空）。

### 方案转向：B（反射 + 命名启发式）

InstructionAnalyzer 改造为**运行时反射 `get_property_list` + 命名启发式筛选**（替代原 codegen 自描述）：
- 变量引用：`*_variable`（配对 `*_variable_scope`），type == TYPE_STRING
- 节点引用：`*_node` / `*_node_path`（NodePath 类型 + String 类型动态属性）
- mode 启发式：`target_`=write, `from_`=read, 其他=read_write

覆盖所有组件（动态 + @export 都走反射），不需 codegen / 自描述 / 改 165 组件。
