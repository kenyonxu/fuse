# 可视化逻辑也能单步调试：Fuse 的断点、执行追踪与实时变量监视

上一篇我们用指令生成器把节点方法一键变成了正式指令，指令库越搭越厚。但指令一多，问题就跟着来了——明明接上了 `SetVariable`，运行时变量却还是旧值；`ForLoop` 循环到第三轮突然走错分支；事件触发链跨了三个 Trigger，到底谁先执行？传统可视化插件的答案通常是"加个打印语句猜一猜"。看完这篇你会知道，Fuse 给可视化逻辑配了一套和写代码一样完整的调试武器：能打条件断点、能跳过前 N 次命中、能回放整条执行链、还能在底部 Dock 实时盯着变量画折线图。可视化不等于黑盒，这是 Fuse 护城河的第 13 块拼图。

## 可视化调试到底难在哪

写 GDScript 出了问题，你可以 `print()`、可以打断点、可以单步、可以看调用栈。可视化系统天然缺这些——指令是一堆 Resource 配置，执行链在 `ActionRunner` 内部按序跑，变量存在 `ExecutionContext` 里，外部根本看不见。大多数同类工具的调试体验止步于"在某个指令里加一行日志"，连"这条指令到底有没有被执行"都要靠猜。

Fuse 的破法是**把调试做成一等公民**：三个专用调试指令覆盖从打日志到断点的完整链路，两个编辑器组件提供执行回放和变量监视，断点还支持表达式条件和命中次数控制。

## 调试指令三件套

**`Print`（打印消息）** 是最轻的一个。只有一个 `message` 属性，执行时输出到 Godot 输出窗口和 `ExecutionContext` 日志，格式 `[PrintInstruction] 你的消息`。适合标记执行流程。

**`PrintVariableValue`（打印变量值）** 解决"变量现在等于几"。按类型格式化输出——String 带引号、Vector2 显示坐标、Color 显示 RGBA、null 直接打 null。支持 Local/Scope/Global 三层作用域。

**`BreakpointInstruction`（断点）** 是重武器，把"日志+变量快照+条件+暂停"合到一条指令里。

| 特性 | Print | PrintVariableValue | BreakpointInstruction |
|---|---|---|---|
| 自定义消息 | 支持 | 不支持 | 通过 label |
| 输出变量 | 不支持 | 单个变量 | 全部变量快照 |
| 条件触发 | 不支持 | 不支持 | 表达式条件 |
| 暂停执行 | 不支持 | 不支持 | 编辑器暂停 |
| 忽略次数 | 不支持 | 不支持 | 支持 |
| 导出构建 | 正常 | 正常 | 降级为日志 |

## 断点进阶：这才是护城河

**条件断点。** 开启 `use_expression_condition` 写表达式，只在条件为真时触发。调试"血量低于 30 时伤害结算"，写 `{scope:health} < 30` 即可。

**跳过前 N 次命中。** 设 `ignore_count = 3`，前 3 次跳过，第 4 次才开始输出。

**命中暂停。** 开启后游戏暂停，变量快照打出，按 Enter 恢复。**仅编辑器生效**，导出构建自动降级为日志。

**作用域来源。** 四档选择——Nearest/Custom ID/Trigger Scope/Target Node，精确锁定要看的容器。

## 执行追踪：DebugVisualizer + ExecutionTracker

`ExecutionTracker` 记录每次指令的开始、完成、错误和性能瓶颈。`DebugVisualizer` 渲染成可点击的树，颜色编码：绿=成功、红=错误、黄=性能问题、蓝=开始。

五套官方工作流：
1. **快速排查**：Print → PrintVariableValue → 定位后删调试指令
2. **断点调试**：BreakpointInstruction → 看输出快照
3. **性能分析**：跑序列 → 看红黄记录 → 导出 JSON
4. **条件断点调试**：开条件表达式 → 只在特定场景触发
5. **Topology 静态分析**：编辑阶段直接看问题标注

## 变量监视器：实时面板才是真护城河

嵌在编辑器底部 Dock，0.5 秒轮询展示所有变量，分三层：Local/Scope/Global。

五个差异化特性：
- **双击编辑**：当场改变量值，不用重跑
- **折线图 60 秒录制**：选变量看历史曲线，只记录 int/float
- **快照导出**：一键导出 JSON 存证
- **静态声明补全**：不运行也能看变量引用关系
- **三层颜色区分**：一眼知道变量活在哪层

## 实战：调一个"伤害结算不生效"的 bug

Print 标流程 → PrintVariableValue 查变量 → BreakpointInstruction 条件暂停看快照 → 变量监视器看折线图 → 快照导出留档。从轻到重，每一步都有对应工具。

## 小结

Fuse 的调试体系用"三条调试指令 + 断点四项进阶 + 执行追踪 + 变量监视器"织成了一张网。但这些都是单点调试——项目变大后更难的是全局视角。下一篇讲 Topology 拓扑主屏，把全场景 Trigger 关系画成一张图，自带静态分析，不用运行就能标红问题。
