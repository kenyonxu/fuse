# 不想等官方出新指令？用 Fuse 生成器从节点方法一键生成指令

上一篇我们用 21 个节点操作指令管好了整个游戏世界，但留下了一个问题：当你的项目里塞满了自定义节点，每个都带着一大堆专有方法——角色的 `dash()`、武器的 `combo_attack()`、机关的 `trigger()`——你当然可以用 `RunTargetNodeFunction` 临时调用它们，但每次都要在 Inspector 里填方法名、配参数、设返回值变量，重复又繁琐，策划更是看不懂。看完这篇你会明白 Fuse 为什么不是一个"功能堆砌"的插件：它把扩展能力直接交到了你手里。你写好的节点方法，右键一键就变成指令库里正式的、可复用的、带参数面板的指令资源，永远不用等官方更新。这就是 Fuse 的护城河——指令生成器。

承接上一篇：节点操作指令够用了，但自定义节点的方法怎么办？生成器就是答案。

## 插件生态的老问题

传统的 Godot 插件，无论做得多好，都有一个天花板：作者提供了多少指令，你就能用多少。你的项目里有个独特的"钓鱼小游戏"节点，你想让策划在 Trigger 里调用它——对不起，插件没这个指令。

这种"等官方出新指令"的被动局面，在 Fuse 里被打破了。生成器的核心思想是：**你写的节点，就是你的指令库**。任何一个节点的公开方法和可写属性，都能在几次点击后变成指令选择器里正式的一员，带分类、带图标、带参数面板，和内置指令一视同仁。

## 入口：右键场景树节点

生成器的入口非常轻。在场景树里右键点击任意节点，选择"生成指令..."，就会弹出对话框。

弹出的对话框分两个标签页：**方法标签页**和**属性标签页**。

方法标签页列出节点所有可用方法，按继承链分组。选中任一方法，右侧显示完整签名和参数列表。属性标签页列出所有可写属性，同样按继承链分组，只读属性和以下划线开头的内部属性已自动过滤。

## 三种生成模式

属性标签页底部有三种生成模式：**SET**（生成设置属性值指令）、**GET**（生成读取属性值指令）、**两者都生成**。方法标签页直接生成调用指令，有返回值的方法自动提供 `result_variable` 来存返回值。

## 变量绑定：护城河里的护城河

如果说"能生成指令"是表层的便利，那"变量绑定"才是生成器真正的差异化所在。

不勾选时，生成"直接赋值"版本，参数在 Inspector 里写死。勾选时，生成"变量绑定"版本，每个参数都能选择来源：直接值或变量。选变量后可以指定变量名和作用域（Local/Global/Scope）。

这种设计意味着同一个生成指令能同时服务于两种场景：策划想要固定值时填直接值，想要运行时动态计算时绑变量。一个指令顶两个用。

## 命名规则与文件存放

生成的指令存放在 `res://fuse_generated/instructions/` 下，按节点类名分子目录。命名规整：方法指令 `{类名}_{方法名}.gd`，SET 属性 `set_{类名}_{属性名}.gd`，GET 属性 `get_{类名}_{属性名}.gd`。

生成后自动注册到 InstructionRegistry，在指令选择器的"用户生成"分类下就能找到。重启编辑器自动重新扫描，团队协作把 `fuse_generated/` 提交 Git 即可。

## 实战：给你的角色生成 dash 指令

假设你写了一个 Player 节点，里面有自定义方法 `dash(direction: Vector2, distance: float) -> void`。

第一步，右键 Player 节点选"生成指令..."。第二步，方法标签页搜索 "dash"。第三步，勾选"使用变量"（方向从输入动态读）。第四步，点击生成，文件存到 `res://fuse_generated/instructions/player/player_dash_with_variable.gd`。第五步，在任意 Trigger 的指令选择器"用户生成"分类里拖入这个指令，配好参数。

整个过程不超过一分钟。现在这个指令是你项目指令库的正式成员。

## 与 RunTargetNodeFunction 的对比

`RunTargetNodeFunction` 是"临时调用"——灵活即用即走，但每次重新配、方法签名一变所有引用都要改。

生成器产出的是"沉淀资源"——一次生成处处复用，有名称、分类、图标和参数面板。方法签名变了重新生成覆盖即可。

一句话总结：`RunTargetNodeFunction` 是"打电话叫人办事"，生成器是"把办事流程写成规章制度"。

## 顺带：图标管理器

生成指令得有图标才专业。Fuse 提供两套图标系统：内置图标引用 Godot 自带的 1011 个图标，自定义图标从图标库取。配套三个工具脚本管理图标同步。

## 为什么这是护城河

不在于 174 个内置指令——别的插件也能堆数量。不在于可视化编辑——这早不是新鲜事。真正的护城河在于：**Fuse 把"扩展指令库"这件事的门槛降到了右键一次点击**。

这意味着两件事。第一，Fuse 的指令生态是"用户驱动"的，每个团队都能长出自己的专属指令库。第二，程序员和策划的分工被重新定义了：程序员写节点方法，策划用生成器把方法变成指令并搭逻辑，中间没有"求程序员加个指令"的沟通损耗。

## 小结

指令生成器用"右键生成 + 变量绑定 + 自动注册"三件套，把你写的节点方法变成了无限增长的指令库。不过指令越搭越多，迟早会出问题——下一篇我们就讲怎么排查这些坑：Fuse 的断点、执行追踪和实时变量监视器，让可视化逻辑也能像写代码一样单步调试。
