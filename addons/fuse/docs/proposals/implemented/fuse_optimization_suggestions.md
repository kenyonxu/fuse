# Fuse 插件优化建议文档

> **STATUS: ✅ 已实现** (2026-06-26 归档) — 本文件是实施方案的前置建议,三大优化点同 [实施方案](fuse_optimization_implementation_plan.md) 一并落地。

## 1. 概述
基于对 Fuse 核心架构的分析，本文档旨在提出针对性的优化建议。考虑到 Fuse 的应用场景是游戏开发，优化重点将集中在**运行时性能 (Runtime Performance)**、**内存管理 (Memory Management)** 和 **数据持久化策略 (Persistence Strategy)** 上，以确保插件在处理高频逻辑和复杂状态时依然保持流畅。

## 2. 运行时性能优化

### 2.1 指令执行路径优化
*   **现状**: `BaseInstruction` 依赖 `finished` 信号来通知完成。虽然灵活，但对于大量的同步指令（如数学计算、变量赋值），信号调用的开销显著高于直接函数调用。
*   **建议**:
    *   引入 `execute_sync(context) -> bool` 接口。
    *   对于同步指令，`ActionRunner` 可以直接在循环中调用 `execute_sync`，仅在返回 `false`（表示需要异步等待）时才挂起并监听信号。这将大幅减少同步指令序列的执行开销。

### 2.2 变量查找优化
*   **现状**: `ExecutionContext` 使用字符串键的 `Dictionary` (`local_variables`) 进行变量查找。字符串哈希查找虽然快，但在极高频调用下仍有成本。
*   **建议**:
    *   **预编译**: 对于静态确定的变量访问，可以在编辑阶段将其解析为索引。
    *   **StringName**: 强制内部使用 `StringName` 作为字典键，利用 Godot 对 `StringName` 的优化（比较指针而非字符串内容）。

## 3. 内存管理与资源

### 3.1 避免不必要的资源复制
*   **现状**: `Trigger._ready()` 中，如果检测到 `event_definition` 引用计数 > 1，会调用 `duplicate()`。这是一个防御性编程，但如果是大型资源，复制成本很高。
*   **建议**:
    *   引入 `RuntimeEventInstance` 概念。`BaseEvent` 仅作为配置数据（只读），运行时状态（如定时器、状态标记）封装在轻量级的 `RuntimeEventInstance` 中。
    *   这样多个 Trigger 可以安全地共享同一个 `BaseEvent` 资源，而无需复制，每个 Trigger 仅持有自己的轻量级运行时实例。

### 3.2 严格的引用清理
*   **现状**: `ExecutionContext` 持有 `target` (Node) 和 `trigger` (Node) 的引用。
*   **建议**:
    *   确保 `ActionRunner` 在执行结束或被中断时，强制调用 `ExecutionContext.cleanup()`。
    *   对于异步长时间运行的指令，使用 `WeakRef` 持有节点引用，防止指令阻碍节点被释放（虽然 Godot 的 `queue_free` 比较安全，但悬空引用会导致报错）。

## 4. 数据持久化策略

### 4.1 写入策略优化
*   **现状**: `GlobalVariableManager` 目前似乎倾向于“变更即保存”或频繁保存，以确保数据安全。这在游戏运行时是不可接受的（IO 操作会造成卡顿）。
*   **建议**:
    *   **脏标记 (Dirty Flag)**: 仅当变量值实际发生改变时标记为 Dirty。
    *   **批量写入 (Batch Save)**: 提供 `save_all_modified()` 接口，仅在特定时机（如存档点、关卡结束、游戏暂停）调用，而不是由变量变更自动触发。
    *   **异步保存**: 如果支持，将序列化和写入操作放入子线程。

### 4.2 变量容器优化
*   **现状**: `VariableContainer` 管理了所有作用域变量。
*   **建议**:
    *   对于大量临时变量，考虑使用数组而非字典，特别是如果变量名在编译期已知。
    *   分离 `RuntimeVariables`（不保存）和 `PersistentVariables`（需保存），避免序列化时不必要的遍历。

## 5. 编辑器与开发体验

### 5.1 静态分析
*   **建议**: 在编辑器中增加静态分析工具。
    *   检测指令中引用的变量名是否存在。
    *   检测可能的死循环（如指令序列中无等待的跳转）。

### 5.2 调试可视化
*   **建议**:
    *   **运行时断点**: 允许在指令上打断点，暂停 `ActionRunner`。
    *   **执行路径高亮**: 在编辑器中实时高亮当前正在执行的指令节点。

## 6. 总结
Fuse 的基础架构稳固，但在应对高性能游戏需求时，需从**减少内存分配**、**降低调用开销**和**优化 IO 策略**三个维度进行改进。引入对象池和优化指令执行流是最具性价比的优化方向。
